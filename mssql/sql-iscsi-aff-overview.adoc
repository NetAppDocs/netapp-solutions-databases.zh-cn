= 了解采用 iSCSI LUN 的 NetApp AFF 上的 SQL Server 2025
:allow-uri-read: 


[role="lead"]
SQL Server 2025 可以将数据库存储在运行 ONTAP 的 NetApp AFF 系统的 iSCSI LUN 上。了解此配置的优势、解决方案组件和设计原则，多路径如何在路径和控制器故障期间使数据库保持在线，以及 NetApp Console 备份和恢复如何保护数据库。

iSCSI 通过标准 TCP/IP 以太网网络传输 SCSI 块命令。对于 Windows 和 SQL Server，iSCSI LUN 是本地磁盘：它使用 NTFS 进行初始化、分区和格式化，并获得驱动器号或挂载点。基于 iSCSI 的块存储是 SQL Server 最广泛使用和最容易理解的存储选项，每个 SQL Server 功能和每个第三方工具都支持它。

AFF 全闪存系统上的 ONTAP 原生实现 iSCSI。结合 SQL Server 2025、Windows Server 2025 和 Microsoft MPIO 框架，这提供了一种存储架构，可提供始终如一的低延迟，容忍路径和控制器的故障，并与 NetApp 数据保护集成。

要部署此配置，请参见 link:sql-iscsi-aff.html["使用 iSCSI LUN 在 NetApp AFF 上部署 SQL Server 2025"]。



[[benefits-of-sql-server-on-iscsi-with-netapp-ontap]]
[[why]]
== 采用 NetApp ONTAP 的 iSCSI 上的 SQL Server 的优势

[cols="1,3"]
|===
| 优势 | 说明 


| 通用兼容性 | iSCSI LUN 是用于 Windows 的本地 NTFS 磁盘。SQL Server、其工具和第三方应用程序不需要特殊配置；本地服务帐户和虚拟帐户正常工作。 


| 标准以太网 | iSCSI 在数据中心现有的以太网网络上运行。无需光纤通道架构、HBA 或 FC 交换机。 


| 高可用性 | 采用 ALUA 的 MPIO 使用多条路径连接到 HA 对的两个节点。路径故障、ONTAP 接管/交还和无中断升级由 Windows 多路径驱动程序透明地处理。 


| 性能 | AFF 系统提供始终如一的低延迟。多个 iSCSI 会话跨多个网络路径和端口分布 I/O。 


| 存储效率 | 精简配置、实时重复数据删除、压缩和压实减少了数据库和备份所使用的物理容量。SCSI UNMAP 将释放的块返回给聚合。 


| 集成数据保护 | ONTAP 快照、SnapRestore、FlexClone 和 SnapMirror 由 NetApp Console 备份和恢复进行编排，可在几秒钟内提供备份，在几分钟内完成还原，并提供即时数据库克隆。 


| 联机容量管理 | 可以在 ONTAP 中在线扩展卷和 LUN，并且可以在 Windows 中在线扩展 NTFS 卷。 
|===


[[solution-components]]
[[architecture]]
== 解决方案组件

解决方案包括以下组件：

[cols="1,3"]
|===
| 组件 | 角色 


| Windows Server 2025 主机 (`{host}`） | 运行 SQL Server 2025。SQL Server 二进制文件和系统数据库位于本地磁盘上 `C:`；用户数据库、日志、TempDB 和日志备份位于四个 NetApp LUN 上。 


| Microsoft iSCSI 启动程序和 MPIO | 将主机连接到 SVM 的 iSCSI LIF，并将每个 LUN 的路径合并到一个多路径磁盘中。 


| SQL Server 2025 | 数据库引擎，默认实例 `MSSQLSERVER`。 


| Active Directory 和 DNS | 域成员身份、SQL Server 管理员的 Windows 身份验证、名称解析和时间同步。 


| NetApp AFF A50 HA 对 | 两个具有共享 NVMe 存储的控制器。如果一个控制器发生故障或升级，配对节点将接管其存储，并且配对节点的 iSCSI 路径将变为活动状态。 


| SVM `{svm}` | 为 iSCSI 目标提供每个节点两个 iSCSI LIF、启动程序组 `{igroup}`和四个 LUN，每个 LUN 都位于自己的 FlexVol volume 中。 


| NetApp Console 备份和恢复 | 创建应用程序一致性快照备份，并提供还原、克隆和复制。 
|===

[[design-principles]]
[[design]]
== 设计原则

该设计遵循基于 ONTAP SAN 存储的 SQL Server 的 NetApp 最佳实践：

* *每个文件类型单独的 LUN 和卷。*数据、事务日志、TempDB 和日志备份放置在不同的 LUN 上，每个 LUN 都在自己的 FlexVol volume 中。每个卷都可以有自己的大小、QoS、效率、快照和复制设置，并且数据卷的快照永远不会包含 TempDB。
* *卷分布在两个节点上。*数据和备份卷在节点 1 上，日志和 TempDB 卷在节点 2 上，因此两个控制器都可以执行有效工作。
* *每个节点两个 iSCSI LIF。*每个 LUN 可通过四条路径到达：两条通过拥有 LUN 的节点的活动/优化路径，以及两条通过 HA 配对节点的活动/非优化路径。
* *带有 Microsoft DSM 的 MPIO。*NetApp Windows Host Utilities 设置建议的超时和多路径策略。
* *数据库卷上采用精简配置，且没有计划的 ONTAP 快照。*备份必须与应用程序一致；它们由 NetApp Console 备份和恢复创建。
* *专用 iSCSI 网络。*为 iSCSI 使用专用 NIC 或 VLAN，端到端配置巨型帧（MTU 9000）。

[[mpio]]
== 多路径如何保护 SQL Server

ONTAP 使用非对称逻辑单元访问（ALUA）来告诉主机哪些路径最佳。通过拥有 LUN 的节点的 iSCSI LIF 的路径报告为*活动/优化*。通过 HA 配对节点的 LIF 的路径报告为*活动/未优化*；在这些路径上发送的 I/O 通过集群互连转发。Microsoft DSM 仅在优化路径（策略*带子集的轮询*）上发送 I/O，并将非优化路径保留为备用。

如果路径出现故障，MPIO 将继续使用剩余的优化路径。如果所属节点发生故障或因升级而被接管，则伙伴节点将接管聚合，ONTAP 会报告新的 ALUA 状态，并且 MPIO 会将 I/O 移动到新的优化路径。SQL Server 只会看到短暂的 I/O 暂停；数据库将保持联机状态。

[[data-protection-with-netapp-console-backup-and-recovery]]

== 使用 NetApp Console 备份和恢复进行数据保护

*NetApp Console* 是 NetApp 用于存储和数据服务的统一控制平面。其*备份和恢复*服务通过应用程序一致性快照保护 ONTAP 上的 Microsoft SQL Server 数据库，并且可以将它们复制到辅助 ONTAP 系统和对象存储。



[[architecture]]
[[console-architecture]]
=== 架构

解决方案包括以下组件：

* *NetApp Console* （SaaS）：用于清单、策略、计划、还原和克隆、作业监控、基于角色的访问控制和通知的 Web 界面。
* *控制台代理*：数据中心中连接控制台与 ONTAP 集群和 SQL Server 主机的 Linux 虚拟机。它仅通过出站 HTTPS 与控制台通信。
* *适用于 SQL Server 和 Windows 的 SnapCenter 插件*：由控制台部署到 SQL Server 主机。它发现实例及其数据库，将数据库文件映射到 NetApp LUN，并在备份期间静默 SQL Server。该插件在端口 8145 上侦听，并且在主机上需要 PowerShell 7 和 .NET。
* *ONTAP*：创建卷 `sql_iscsi_1_data`和 `sql_iscsi_1_log`的快照，并执行 SnapRestore 和 FlexClone 操作。SQL Server 本身继续通过 iSCSI 访问其文件。

[[how-a-local-snapshot-backup-works]]
[[console-workflow]]
=== 本地快照备份的工作原理

. NetApp Console 启动备份作业，由保护策略计划或按需启动。
. 该插件使用 SQL Server VDI/VSS 接口将数据库的写入 I/O 冻结几秒钟。
. ONTAP 创建数据和日志卷的一致快照(`sql_iscsi_1_data`， `sql_iscsi_1_log`）。未复制任何数据。
. 数据库恢复，备份记录在 SQL Server 备份历史记录 (`msdb`）和 Console 目录中，连同其保留信息一起。
. 事务日志备份以短间隔（例如每 15 分钟）运行 `H:\backup`，并允许时间点恢复。
. 可选：快照使用 SnapMirror 复制到辅助 ONTAP 系统，或备份到对象存储，以实现 3-2-1 备份策略。

[[console-benefits]]
=== 适用于 SQL Server 的 NetApp Console 的优势

* *数秒内完成备份。*对于任何大小的数据库，快照备份只需几秒钟即可完成；备份窗口几乎不复存在。
* *不会影响性能。*不会在主机上或通过网络读取或复制任何数据。SQL Server 只会静默几秒钟。
* *几分钟内还原。*数据库文件几乎立即从快照中还原。结合日志备份，您可以恢复到任何时间点。
* *节省空间的备份。*快照仅存储更改的块，因此您只需极少的额外容量即可保留许多还原点。
* *即时克隆。*FlexClone 可在几秒钟内创建生产数据库的可写副本，用于开发、测试、报告或故障排除。在数据更改之前，它们不会使用额外的容量。
* *通过一个策略实现 3-2-1 保护。*本地快照、到辅助 ONTAP 系统的复制以及到对象存储的备份（例如 NetApp StorageGRID 或公有云）均在同一个保护策略中配置。
* *无需维护备份基础架构。*控制平面作为服务提供；仅轻量级 Console 代理在本地运行。没有要安装、修补或保护的备份服务器或目录数据库。
* *集中管理。*所有 SQL Server 主机的清单、策略、计划、保留、基于角色的访问控制、作业监控和通知都在一个 Web 界面中，并具有用于自动化的 REST API。
* *从 SnapCenter 平滑过渡。*可以将现有 SnapCenter 配置导入到 NetApp Console。
* *勒索软件弹性。*ONTAP 快照为只读，但特权用户可以删除未锁定的快照。使用具有保留期的 ONTAP 防篡改快照锁定来防止删除，并在支持的情况下将其与自主勒索软件保护相结合。
