= 使用 iSCSI LUN 在 NetApp AFF 上部署 SQL Server 2025
:allow-uri-read: 


[role="lead"]
在 Windows Server 2025 上部署 SQL Server 2025，并将用户数据库、事务日志、TempDB 和日志备份放置在 NetApp AFF 系统的 iSCSI LUN 上。此过程包括在 ONTAP SVM 上配置 iSCSI、配置启动程序组和 LUN、配置 Windows iSCSI 启动程序、MPIO 和磁盘，以及安装 SQL Server。



[[scope]]
[[intro-scope]]
== 范围

此过程在单个 Windows Server 2025 主机上部署独立的 SQL Server 2025 实例，并在 iSCSI LUN 上配置用户数据库、事务日志、TempDB 和日志备份。相同的存储设计适用于 SQL Server 故障转移集群实例（FCI）和 Always On 可用性组，但不包括其特定于集群的配置。SQL Server 性能调整和规模估算也超出了范围。有关优势、解决方案组件、设计原则、多路径工作原理以及使用 NetApp Console 备份和恢复进行数据保护的说明，请参阅 link:sql-iscsi-aff-overview.html["了解采用 iSCSI LUN 的 NetApp AFF 上的 SQL Server 2025"]。



[[audience]]
[[intro-audience]]
== 受众

此过程用于：

* *存储管理员*，负责配置 ONTAP 集群、SVM、iSCSI LIF、启动程序组和 LUN。
* *Windows 管理员*，负责准备 Windows Server 2025 主机、iSCSI 启动程序、MPIO 和磁盘。
* *数据库管理员*，负责安装和配置 SQL Server 2025 并设置备份和恢复。


假设您具备 ONTAP System Manager、Windows Server 和 SQL Server 管理的基本知识。

TIP: 在不同控制器上使用其他 LUN 用于其他辅助数据文件 (.ndf) 以分散负载。



[[prerequisites]]
== 前提条件

在开始之前，请确保满足以下要求：

.NetApp ONTAP
* AFF HA 对已安装，并且集群已设置且运行正常。
* 已安装 iSCSI 许可证。它包含在 ONTAP One 中。
* 每个节点上至少存在一个数据聚合（本地层）。
* SVM 存在。在此过程中，将使用现有的 SVM `{svm}`；向其添加 iSCSI。要为 SAN 创建专用 SVM，请使用 menu:Cluster[Storage VMs > Add] 并选择 *iSCSI* 作为访问协议。
* iSCSI LIF 的数据网络端口、广播域和（可选）VLAN 已配置。在实验室中，广播域 `MT9000`使用巨型帧。
* 时间通过 NTP 在集群、主机和 Active Directory 之间同步。


.网络
* SQL Server 主机在 iSCSI 子网或 VLAN 中至少有一个（最好是两个）iSCSI 专用 NIC。
* MTU 在端到端（主机 NIC、交换机、ONTAP 端口）保持一致。从主机使用 `ping -f -l 8972 <LIF-IP>`验证巨型帧。


.Windows Server
* Windows Server 2025（桌面体验）已安装、修补并加入域。
* 支持 Windows Server 2025 的 NetApp Windows 主机实用程序版本现已可用（请参阅 https://imt.netapp.com/matrix/["NetApp 互操作性矩阵工具 (IMT)"^]）。
* SQL Server 2025 安装介质（ISO）和有效的产品密钥（或免费版本）可用。



NOTE: 与 SMB 文件共享不同，LUN 不需要 SQL Server 服务的域帐户。可以使用默认虚拟帐户 (`NT Service\MSSQLSERVER` ）。如果实例需要网络访问，例如备份到文件共享或进行 Kerberos 身份验证，则仍建议使用域帐户或 gMSA。

[[step-5-review-the-volume-and-lun-settings]]
[[volume-settings]]
== 第 5 步：查看卷和 LUN 设置

查看四个卷的空间和快照设置。System Manager 使用合理的默认值；建议对 SQL Server LUN 进行以下设置：

[cols="1,1,3"]
|===
| 设置 | 值 | 原因 


| 空间保证（卷） | `none` （精简） | 只有在写入数据时才会占用容量。 


| LUN 空间预留 | `disabled` （精简） | 精简卷中的精简 LUN。 


| LUN 空间分配 | `enabled` | 启用 SCSI UNMAP，以便将 NTFS 中释放的空间返回到 ONTAP，并允许主机在卷空间耗尽时正确响应。 


| Snapshot 策略 | `none` | 不符合应用程序一致性的快照对 SQL Server 无用。备份由 NetApp Console 备份和恢复创建。 


| Snapshot 预留 | `0` % | 改为使用卷自动调整大小来监控 Snapshot 空间。 


| 自动调整大小 | `grow`，最大值约为卷大小的 130% | 防止快照占用空间时 LUN 脱机。 


| 存储效率 | 已启用（在 AFF 上默认） | 实时重复数据删除、压缩和压实不会对 SQL Server 性能产生可衡量的影响。 
|===
使用以下命令应用并验证设置（针对 `sql_iscsi_1_data`显示）：

[source, console]
----
cluster::> volume modify -vserver a50-sql -volume sql_iscsi_1_data -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
cluster::> lun modify -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1 -space-allocation enabled
cluster::> volume show -vserver a50-sql -volume sql_iscsi_1_* -fields aggregate,size,space-guarantee,snapshot-policy,autosize-mode
----

NOTE: 在现有 LUN 上更改 `space-allocation` 需要该 LUN 处于脱机状态。请在创建时或在主机连接到 LUN 之前进行设置。

.PowerShell

以下命令使 NetApp 磁盘联机，使用 GPT 对其进行初始化，在每个磁盘上创建并格式化一个分配单元大小为 64K 的 NTFS 卷，并为 SQL Server 创建文件夹。

[source, powershell]
----
PS C:\> $layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
PS C:\> foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
          $l = $layout[[int64]$d.Size]
          Set-Disk -Number $d.Number -IsOffline $false
          Set-Disk -Number $d.Number -IsReadOnly $false
          Initialize-Disk -Number $d.Number -PartitionStyle GPT
          New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
            Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
        }
PS C:\> 'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ }
PS C:\> Get-Volume -DriveLetter E,F,G,H | Format-Table DriveLetter,FileSystemLabel,FileSystem,AllocationUnitSize,Size
----

+

SELECT DB_NAME(database_id) AS database_name,

----

[source, sql]

[[use-a-powershell-script-to-configure-the-host-in-one-pass]]
[[ps-script]]
== 使用 PowerShell 脚本一次性配置主机

以下脚本包含此过程中的完整主机配置。在提升的 PowerShell 会话中运行它；MPIO 部分需要重新启动。

[source, powershell]
----
# --- Part 1: iSCSI service and MPIO (restart required) ------------------------
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI
(Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress   # initiator IQN for the igroup
Install-WindowsFeature -Name Multipath-IO
Enable-MSDSMAutomaticClaim -BusType iSCSI
# Install NetApp Windows Host Utilities (MPIO support) now, then:
Restart-Computer

# --- Part 2: connect the iSCSI sessions (after the LUNs are mapped in ONTAP) ---
$initiatorIP = '192.168.175.44'
$lifs        = '192.168.175.134','192.168.175.135','192.168.175.136','192.168.175.137'
New-IscsiTargetPortal -TargetPortalAddress $lifs[0] -InitiatorPortalAddress $initiatorIP
$target = Get-IscsiTarget | Where-Object NodeAddress -like 'iqn.1992-08.com.netapp:*'
foreach ($lif in $lifs) {
    Connect-IscsiTarget -NodeAddress $target.NodeAddress -TargetPortalAddress $lif `
        -InitiatorPortalAddress $initiatorIP -IsMultipathEnabled $true -IsPersistent $true
}
Get-IscsiSession | Format-Table TargetNodeAddress,InitiatorPortalAddress,IsConnected,IsPersistent
mpclaim -s -d

# --- Part 3: disks, volumes and folders ---------------------------------------
$layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
    $l = $layout[[int64]$d.Size]
    Set-Disk -Number $d.Number -IsOffline $false
    Set-Disk -Number $d.Number -IsReadOnly $false
    Initialize-Disk -Number $d.Number -PartitionStyle GPT
    New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
        Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
}
'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force }

# --- Part 4: firewall for SQL Server -----------------------------------------
New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----

NOTE: 分别运行每个部分。第 1 部分需要重新启动主机，因此其他部分在重新启动后不会继续。


CAUTION: 仅当这些 LUN 是连接到系统的唯一 RAW LUN 时，才运行第 3 部分中的命令。如果有其他 RAW LUN 连接到系统，则需要手动创建文件夹并格式化卷。
