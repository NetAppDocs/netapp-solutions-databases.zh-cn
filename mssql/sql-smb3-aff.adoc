[role="lead"]
在 Windows Server 2025 上部署 SQL Server 2025，并将用户数据库、事务日志、TempDB 和备份放置在 NetApp AFF 系统上持续可用的 SMB 3 共享上。此过程包括配置 ONTAP SVM、卷和共享，然后安装 SQL Server。



[[scope]]
[[intro-scope]]
== 范围

此过程在单个 Windows Server 2025 主机上部署独立的 SQL Server 2025 实例，并在 SMB 3 连续可用（CA）共享上部署用户数据库、事务日志、TempDB 和备份。相同的存储设计适用于 SQL Server 故障转移群集实例（FCI）和 Always On 可用性组，但不涵盖其特定于群集的配置。SQL Server 性能调整和规模估算也超出了范围。有关优势、解决方案组件、设计原则以及持续可用性工作原理的说明，请参阅 link:sql-smb3-aff-overview.html["了解具有 SMB 3 持续可用性的 NetApp AFF 上的 SQL Server 2025"]。



[[audience]]
[[intro-audience]]
== 受众

此过程用于：

* *存储管理员*，负责配置 ONTAP 集群、SVM、卷和 SMB 共享。
* *Windows 和 Active Directory 管理员*，负责准备 Windows Server 2025 主机、服务帐户和网络。
* *数据库管理员*，负责安装和配置 SQL Server 2025 并设置备份和恢复。


假设您具备 ONTAP System Manager、Windows Server 和 SQL Server 管理的基本知识。

[[prerequisites]]
== 前提条件

在开始之前，请确保满足以下要求：

.NetApp ONTAP
* AFF HA 对已安装，并且集群已设置且运行正常。
* 已安装 CIFS （SMB） 许可证。它包含在 ONTAP One 中。
* 每个节点上至少存在一个数据聚合（本地层）。
* 通过 NTP 在群集和 Active Directory 之间同步时间。Kerberos 允许的最大时钟偏差为 5 分钟。
* SMB LIF 的数据网络端口、广播域和（可选）VLAN 已配置。


.Active Directory 和 DNS
* Active Directory 域可用，并且可以从 SVM 数据 LIF 访问 DNS 服务器。
* 您拥有一个帐户，该帐户具有在目标 OU 中为 CIFS 服务器创建计算机对象的权限。
* 专用域用户帐户作为服务帐户可用于 SQL Server 数据库引擎和 SQL Server 代理服务。



IMPORTANT: 当其文件位于 SMB 共享上时，SQL Server 必须在*域帐户*下运行。内置虚拟帐户(`NT SERVICE\MSSQLSERVER`）和本地帐户无法被授予对远程文件共享的访问权限。

.Windows Server
* Windows Server 2025（桌面体验）已安装、修补并加入域。
* SQL Server 2025 安装介质（ISO）和有效的产品密钥（或免费版本）可用。


.ONTAP 上的 SQL Server 的 SMB 要求和限制
* 必须在 SVM 上启用 SMB 3.0 或更高版本。
* 托管 CA 共享的所有卷必须使用 *NTFS* 安全样式，并且从一开始就必须是 NTFS。
* 不支持 SMB Direct (RDMA)。
* 不支持 ReFS。ONTAP (WAFL) 为共享提供文件系统。

== 步骤 2：创建和配置 Storage VM （SVM）

使用专用的 SQL Server SVM。SVM 作为 CIFS 服务器加入 Active Directory，并在 HA 对的每个节点上提供一个 SMB 数据 LIF。

.步骤
. 使用 System Manager 或 CLI 创建 SVM：
+
[role="tabbed-block"]
====
.System Manager
--
.. 在 System Manager 中，转到 menu:Cluster[Storage VMs] 并单击 *+ Add*。
+
.显示示例
[%collapsible]
=====
image:sql25_smb_bp_006.png["集群 > Storage VM > 添加"]

=====
.. 输入*存储 VM 名称* `a50-sql`。在*访问协议*中，选择 *SMB/CIFS、NFS、S3* 选项卡，然后选择*启用 SMB/CIFS*。
+
.显示示例
[%collapsible]
=====
image:sql25_smb_bp_007.png["添加 Storage VM - 名称和协议"]

=====
+

NOTE: Storage VM 名称是 CIFS 服务器的 SMB 名称。

.. 输入 Active Directory 信息（域、管理员名称和密码以及 OU）和 DNS 信息（DNS 域和名称服务器）。
.. 在*网络接口*下，在*每个*节点上配置一个数据 LIF。
+

TIP: 每个节点一个 LIF 为 SQL Server 提供通往每个节点的直接（本地）路径，这是 SMB 多通道和无中断故障转移的先决条件。使用 25 GbE 或更快的端口，并在端到端使用相同的 MTU。

+

NOTE: 您必须在 DNS 服务器中注册这些网络接口。有关详细信息，请参见 https://docs.netapp.com/us-en/ontap-system-manager-classic/smb-config/task_mapping_smb_server_dns_server.html["将 SMB 服务器映射到 DNS 服务器"^]。

.. 单击*保存*。System Manager 创建 SVM、根卷、LIF 和 DNS 配置，并将 CIFS 服务器加入域。
.. 验证 SVM 根卷 (`a50_sql_root` 在实验室中）。它必须使用 *NTFS* 安全样式，否则 SMB 共享将不起作用。转到 menu:存储[卷]，选择根卷，然后单击 *编辑* 以查看其设置。
+
.显示示例
[%collapsible]
=====
image:sql25_smb_bp_012.png["编辑 SVM 根卷 a50_sql_root"]

=====


--
.ONTAP 命令行界面
--
以下命令从 CLI 创建相同的配置。替换尖括号中的占位符值。

[source, console]
----
cluster::> vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs

cluster::> vserver modify -vserver a50-sql -allowed-protocols cifs

cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

cluster::> vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>

====
. [[svm-smb-options,Configure the SMB server options]]配置 SMB 服务器选项。验证是否在 SVM 上启用了 SQL Server 所需的 SMB 选项：
+
[source, console]
----
cluster::> set -privilege advanced
cluster::*> vserver cifs options show -vserver a50-sql -fields smb3-enabled,is-multichannel-enabled,is-large-mtu-enabled,copy-offload-enabled,shadowcopy-enabled
cluster::*> vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
cluster::*> set -privilege admin
----
+
[cols="1,3"]
|===
| 选项 | 目的 


| `smb3-enabled` | 持续可用的共享需要 SMB 3.x。 


| `is-multichannel-enabled` | SMB 多通道使用多个 TCP 连接和网络路径，以提高吞吐量和恢复能力。 


| `is-large-mtu-enabled` | 允许高达 1 MB 的 SMB 读取和写入。 


| `copy-offload-enabled` | ODX 副本卸载；复制操作在存储系统内执行。 


| `shadowcopy-enabled` | SMB 共享的远程 VSS。使用 SMB 共享的 VSS 的备份应用程序所需。 
|===
. 验证 CIFS 服务器已在 DNS 中注册，并且可以从 SQL Server 主机进行解析：
+
[source, powershell]
----
PS C:\> Resolve-DnsName a50-sql.sapcc.stl.netapp.com
----

.显示示例
[%collapsible]

=====

+
.显示示例
[%collapsible]

image::sql25_smb_bp_026.png[带有“编辑”的共享上下文菜单]

*** *访问此共享时加密数据*：已清除（可选，具体取决于您的安全要求）

[[step-6-prepare-windows-server-2025]]
[[windows-prep]]
== 步骤 6：准备 Windows Server 2025

请以域管理员身份在 SQL Server 主机 `{host}`上执行以下步骤。

.步骤
. 验证此服务器是否已加入域，以及 CIFS 服务器是否可以解析（请参阅 <<svm-smb-options>>）。
. 确保 SQL Server 服务帐户存在于 Active Directory 中，例如 `SAPCC\sql1admin`。对数据库引擎和 SQL Server 代理使用相同的帐户，或者为每个服务使用单独的帐户。无论您选择哪种方式，都要授予每个帐户对所有四个共享的访问权限。
. 在服务帐户的安全上下文中测试对共享的访问权限：
+
[source, powershell]
----
PS C:\> runas /user:SAPCC\sql1admin "cmd /c dir \\a50-sql\sql1_data && echo test > \\a50-sql\sql1_data\write-test.txt && del \\a50-sql\sql1_data\write-test.txt"
----
. 在 Windows 防火墙中打开 SQL Server 端口：
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. 验证 SMB 与 SVM 的连接。方言必须为 3.x，并且 `ContinuouslyAvailable`必须为 `True`：
+
[source, powershell]
----
PS C:\> dir \\a50-sql\sql1_data | Out-Null
PS C:\> Get-SmbConnection -ServerName a50-sql | Format-Table ServerName,ShareName,Dialect,ContinuouslyAvailable,Encrypted,Signed
PS C:\> Get-SmbMultichannelConnection -ServerName a50-sql
----



NOTE: 默认情况下，Windows Server 2025 要求对所有出站 SMB 连接进行 SMB 签名。ONTAP 支持 SMB 签名并自动协商。签名会增加双方的 CPU 开销，因此请将其包含在性能测试中。请勿在未经安全审核的情况下禁用签名。



[[step-7-install-sql-server-2025]]
[[sql-install]]
== 第 7 步：安装 SQL Server 2025

使用安装向导在 Windows Server 主机上安装 SQL Server 2025。在本地磁盘上安装二进制文件和系统数据库，并将用户数据库、事务日志、TempDB 和备份位置指向您创建的 SMB 共享。

.步骤
. 从 SQL Server 安装中心启动独立安装。
+
.. 装载 SQL Server 2025 ISO 映像。在文件资源管理器中，打开实验室中的 DVD 驱动器 (`D:`）并双击 *setup*。
+

[[step-8-verify-the-installation-and-create-a-database]]
[[post-install]]
== 第 8 步：验证安装并创建数据库

使用 SQL Server Management Studio (SSMS) 创建测试数据库，并验证其数据和日志文件是否位于 SMB 共享上。（可选）在 ONTAP 上确认打开的文件使用连续可用性。

.步骤
. 从安装中心的 *安装 SQL Server 管理工具* 链接或从 Microsoft 网站安装 SQL Server Management Studio （SSMS）。
. 启动 SSMS 并使用 Windows 身份验证连接到实例 (`sql-1`）。
. 右键单击*数据库*并选择*新建数据库……*。输入数据库名称 (`SQ1` 在实验室中），设置初始文件大小，然后单击*确定*。数据和日志文件路径默认为 `+\\a50-sql\sql1_data+`和 `+\\a50-sql\sql1_log+`。
+
.显示示例
[%collapsible]
====
image:sql25_smb_bp_047.png["具有 UNC 路径的新数据库对话框，width=800"]

====
. 新数据库将显示在*对象资源管理器*中。
+
.显示示例
[%collapsible]
====
image:sql25_smb_bp_048.png["具有数据库 SQ1 的 SSMS 对象资源管理器,width=800"]

====
. 使用 T-SQL 验证文件位置：
+
[source, sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----
. 可选：验证 ONTAP 上打开的文件的持续可用性：
+
[source, console]
----
cluster::> vserver cifs session show -vserver a50-sql
cluster::> vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----
+
所有 SQL Server 文件必须显示 `continuously-available: Yes`。





[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
== 使用 ONTAP CLI 脚本一次性配置存储

以下脚本包含此过程的完整存储配置。在运行之前，请替换尖括号中的值。

[source, console]
----
# --- SVM -----------------------------------------------------------------
vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs
vserver modify -vserver a50-sql -allowed-protocols cifs

network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>
vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers

set -privilege advanced
vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
set -privilege admin

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql1_data    -aggregate <aggr_node1> -size 1TB   -security-style ntfs -junction-path /sql1_data    -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB
volume create -vserver a50-sql -volume sql1_log     -aggregate <aggr_node2> -size 512GB -security-style ntfs -junction-path /sql1_log     -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_tempdb  -aggregate <aggr_node2> -size 500GB -security-style ntfs -junction-path /sql1_tempdb  -space-guarantee none -percent-snapshot-space 0 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_backups -aggregate <aggr_node1> -size 2000GB -security-style ntfs -junction-path /sql1_backups -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 2600GB

# --- CA shares -----------------------------------------------------------
vserver cifs share create -vserver a50-sql -share-name sql1_data    -path /sql1_data    -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_log     -path /sql1_log     -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_tempdb  -path /sql1_tempdb  -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_backups -path /sql1_backups -share-properties oplocks,browsable,changenotify,continuously-available

# --- Share permissions (repeat for each share) ----------------------------
vserver cifs share access-control create -vserver a50-sql -share sql1_data -user-or-group SAPCC\sql1admin -permission Full_Control
vserver cifs share access-control delete -vserver a50-sql -share sql1_data -user-or-group Everyone

# --- Verification ----------------------------------------------------------
vserver cifs show -vserver a50-sql
vserver cifs share show -vserver a50-sql -fields share-name,path,share-properties
vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----

TIP: 将卷分布在两个节点的聚合中，例如节点 1 上的数据和备份，以及节点 2 上的日志和 TempDB。这将使用两个控制器的资源。
